# # TCP とは

- Transmission Contorol Protocol の略。
- 相手との通信に確実性を求める時に使用される。
- 帯域幅を有効に活用したり、混雑した際の緩和も行ってくれて、更にパケットに不備があっても再送なども行ってくれる。
- 確実性を求めるための仕組み上、接続から切断だけでも 7 回の通信を行う必要があるため、速度が求められる通信には向いていない。
- パケットをセグメントといった単位で分けて送信する。スリーハンドシェイクの通信時には最大セグメントサイズを決定させる。通信時のどちらかの応答で最大セグメントサイズが小さいほうを選択して通信が行われる。

# # TCP の階層モデル
- 5 〜 7 層: アプリケーション層
    - TCP/IP では単一のアプリケーションまたは複数のアプリケーションに分けてセッション層、プレゼンテーション層、アプリケーション層が実装される。
- 4 層: トランスポート層
- 3 層: インターネット層
    - IP アドレスを用いてインターネットの接続を行う。
    - TCP/IP ではトランスポート層の役割も担っており、ルーターはこのインターネット層の機能を含み外部のネットワークと接続する。
- 2 層: ネットワークインターフェース層
    - ネットワーク 接続を行うためのマシンとネットワークの間に位置する層。
    - インターフェースといった名前の通り、NIC を扱うためのデバイス ドライバといってもよい。
- 1 層: 物理層
    - イーサネットや電話回線など、TCP/IP の通信を行うのに必要な物理的な配線のこと。
    - 特に帯域幅や遅延などの考慮はされてず、あくまで接続するための層。

# # UDP とは
- User Datagram Protocol の略
- コネクションレス型と呼ばれ、速度が求められる通話やゲーム、ライブ放送などで使用される。
- TCP と異なり再送などもせず、一方的にデータを送り続けるので相手との接続状態などに関してはアプリケーション側で確認する必要がある。

# # TCP/IP の階層モデルと通信例
- 送信されるデータには各階層ごとに対応したヘッダが付与されている。
- ヘッダには送信元や宛先などの通信の際に必要な情報が格納されていて、その後ろにデータが存在している。
- それぞれの階層でのデータ単位の名称
    - パケット:
        どこの階層でも使える一般的な呼び方。
    - フレーム:
        データリンク層で使用されるデータ単位。
    - データグラム:
        ネットワーク層以上で使用されるデータ単位。
    - セグメント:
        TCP/IP でデータを分割した際の単位。
    - メッセージ:
        アプリケーション プロトコルのデータ単位を表すときに使用される。
- ヘッダは各層が使用するビット数、フィールドの配置などが厳格化されているため、異なれば通信を行うことができない。
- ヘッダにはそのプロトコルでどんな種類の通信を行うのか、どこに送るのか、どこから送られるのか、チェックサムの計算方法など通信に関する情報がすべて詰まっている。

# # TCP モジュールの処理
- ホスト間の接続の確立、切断、再送などを担う。
- データの頭に TCP ヘッダを付与する。
- ヘッダにはプロトコルの識別番号やチェックサムの計算方法、アプリケーションが使用しているポート番号、パケットの順番を表すシーケンス番号などを保持している。

# # IP モジュールの処理
- TCP ヘッダの頭に IP ヘッダを付与する。
- IP ヘッダでは送信元、送信先の IP アドレス、IP ヘッダの次は TCP なのか UDP なのかといった情報を保持している。
- IP ヘッダの構成まで出来たらルーティングを決め、ネットワーク ドライバに送信してもらう。
- 通信先の MAC アドレスが不明な場合は ARP を使用して MAC アドレスを取得しイーサネット ドライバに送信してもらう。

# # トランスポート層ではポート番号をもとに送信先を識別する。
- 複数のクライアントから同じポートに対してアクセスされる HTTP のような通信の場合は送信元 IP や送信元ポート番号など送信元の情報で別の通信として識別する。
- 送信元のポート番号を自動的に振り分けるダイナミックポートといった機能もある。

# # TCP で行っている制御について
- ネットワークの利用効率を高めるために、ウィンドウという概念を使用する。ウィンドウを使用するとウィンドウ サイズをもとに受信者から確認応答を待たずにウィンドウ サイズの最大値までセグメントを送ることができる。
    - 基本的には送信者側が流量制御を行っている。
- ふくそう制御にもウィンドウが使われている。
- ウィンドウで初めから大量のセグメントを送るとふくそうが発生する場合があるので、１からはじめて確認応答が返ってくるごとにウィンドウ サイズを増加させていく。
- TCP では確認応答から同じデータ番号が 3 回要求されると送信元は要求されたデータ番号のものを再送する。
- スライド ウィンドウ方式:
    ウィンドウで 1 から 1001 番 ～ 4001 番のデータ処理が行われていて、1 から 1001 番の処理が終われば 1000 番 から 2001 ～ 5001 番のようにスライドして並列処理する。

# # 遅延応答制御について
- ネットワークを効率化するためにも利用される。
- ピギーバック: 遅延応答制御をしていれば確認応答と共にデータも一緒に送ること。
