# # MAC アドレスとは
- データリンク層でホストを識別するための一意の番号 (厳密には一意でない例外もある)。
- イーサネットや無線、LAN (IEEE 802.11) では IEEE 802.3 で規格化された MAC アドレスが利用されている。
- ほか FDDI や ATM、Bluetooth などでも使用。
- 48 ビットの長さを持ち、NIC に MAC アドレスが焼きこまれている。
![[Pasted image 20260913172654.png]]

# # MAC アドレスによる転送
- 同軸ケーブルなどの通信では同時に１つのホストしか送信できないので、ネットワークを効率よく使うためにスイッチング ハブやイーサネット スイッチが登場した。
	- スイッチ ハブやイーサネット スイッチは媒体非共有型で利用されていた技術を応用している。
- イーサネット スイッチは複数のポートを持ったブリッジとした役割を持つ。
- フレームの送信では MAC アドレスをもとに送信が行われるが、この時にどこに送るかを示したものがフォワーディング テーブルという。
- フォワーディング テーブルには自動的に設定されていく。
    - 通信を行うと送信元と宛先の対が記録されていき、同じ次の送信で再利用される。
    - 対の記録は自動学習で設定されていく。
    ![[Pasted image 20260913172832.png]]

# # スイッチの転送方式
- ストア ＆ フォワードとカットスルー方式の 2 種類が存在する。
    - ストア ＆ フォワード
        - FCS をチェックしてから転送する。
        - コリジョンが発生した際や、ノイズによるエラーフレームの転送を防止する。
    - カットスルー
        - フレームの蓄積を待たずに宛先の MAC アドレスが判明次第、送信を行う。
        - 遅延が少ないが、エラーフレームなどは送ってしまうこともある。

# # ネットワーク インターフェース (インターネット ドライバの処理)
- イーサネット ヘッダは IP ヘッダの頭につけられる。
- イーサネットのヘッダには送信元、宛先の MAC アドレス、ヘッダの次のプロトコルを示すイーサネット タイプが格納されている。
- 送信処理中にハードウェアによって FCS (Frame Check Sequence) が計算される。これはパケットに問題がないかを検出するために使用される。

# # データリンクを流れるパケットの様子
- データが送信される際は 7 層 → 1 層、受け取る際は 1 層 → 7 層の流れになる。
    ![[Pasted image 20260913172856.png]]
- 各層に応じて MAC アドレスや IP アドレスを保有し、データリンク層ではイーサネット タイプ、ネットワーク層ではプロトコル タイプ、トランスポート層では 宛先ポート番号を元に次のプロトコルへ処理を流していく。
- FCS は必ず最後につく。

# # データリンクの役割
- TCP/IP の理解を深めるには重要な項目。
- TCP/IP では物理層とデータリンク層が機能していることが前提となっている。
- データリンク層ではツイストペアケーブルなどで物理的に接続された機器間の通信を行う。
- 通信では電気の強弱で 0 と 1 の信号を送って通信を行い、データリンク層ではひとまとまりの通信をフレームとして相手の機器と通信する。

# # ループを検出するための技術
- ネットワークのトポロジーやブリッジによってはコピーされたフレームがループし続け、メルトダウンを起こす可能性がある。
    - メルトダウンとは、異常なパケットがネットワークを埋め尽くす状態のこと。
    - 解決するにはネットワークを切り離したり機器の電源を落としたりしないといけない。
- メルトダウンを防止するために、スパニングツリーといった方式ができた。
- スパニングツリーを使用することでブリッジでループが行うような構成になっても問題なく通信ができ、適切なループ構成をすることで、耐障害性やトラフィックの負荷分散ができるようになった。
    ![[Pasted image 20260913172931.png]]
- スパニングツリー
    - IEEE802.1D で定義されている。
    - Bridge Protocol Data Unit (BPDU) を 1 ～ 10 秒の間隔で各ブリッジとパケット交換を行う。
    - 使用/不使用なポートを決定し、ループを消す。
    - 障害が発生した場合は使用していないポートを使用して通信を維持する。
        - 1 つのブリッジをルートとしてツリー構造を作成する。
        - それぞれのポートに重みをつけ、優先的に使用したいポートや障害時に使用したいポートを設定することができる。
    - スパニングツリーの機能によってブリッジのみでループの解決が可能。
		![[Pasted image 20260913173017.png]]
- ラピッド スパニングツリー
    - IEEE802.1D で定義されているスパニングツリーには、障害時の切り替わりなどに数秒の時間がかかる。そこで、解決するために IEEE802.1W で Rapid Spanning Tree Protocol (RSTP) が定義され、数秒以下の切り替わり時間となった。

# # リンクアグリケーション
- IEEE802.1AX で定義されている。
- 耐障害性と高速化を図れる。
- スパニングツリーと異なり、複数のポートを同時に使用することができる。

# # Link Layer Discovery Protocol
- IEEE802.1AB で定義されている。
- ネットワークに接続されている機器情報を収集する。
- ネットワーク機器はホスト名やインターフェースといった自分の情報を マルチキャスト MAC アドレスに送信して、受信側は LLDP パケットを受信して情報収集する。

# # データリンク層の 2 つの層
- 媒体アクセス制御
    - Media Access Control (MAC) と呼ばれる。
    - イーサネットや FDDI などでデータリンクごとに決まっているヘッダや制御。
- 論理リンク制御
    - Logical Link Control (LLC) と呼ばれる。
    - イーサネットや FDDI に限らずデータリンク共通で使用されるヘッダや制御。
    - IEEE802.3 Ethernet のフレーム フォーマットに付いている。
    - LLC、SNAP ヘッダを調べることで上位層のプロトコルが判明する。
        ![[Pasted image 20260913173347.png]]

# # PPP (Point-to-Point Protocol)
- P2P (1 対 1) で接続するためのプロトコルで OSI 参照モデルでは第二層にあたる。
- イーサネットや FDDI は同軸ケーブルやツイスト ペア ケーブルなど物理層も考慮する必要があるが、PPP は物理層がとりあえずなんでもいいから満たされていればいい。
    ![[Pasted image 20260913173411.png]]
- 電話回線、ISDN、専用回線、ATM 回線などで利用される。
- 最近では ADSL やケーブル テレビなどを使用したインターネット接続で PPPoE (PPP over Ethernet) が利用され、イーサネットのデータ部に PPP のフレームを格納することができる。

# # LCP と NCP
- PPP でのデータ通信を開始する前に PPP レベルでコネクションを確立するために以下の機能がある。
    - LCP (Link Control Protocol: 上位層に依存しないプロトコル)
        - コネクションの確立/切断、パケット長 (Maximum Receive Unit) の設定、認証プロトコルの設定 (PAP か CHAP か)、通信品質の監視をするかどうかの設定など行う。
    - NCP (Network Control Protocol: 上位層に依存するプロトコル)
    - IPCP (IP Control Protocol: 上位層が IP の時の NCP)
        - IP アドレスの設定、IP ヘッダを圧縮するかどうかなどのやりとりを行う。
            ![[Pasted image 20260913173435.png]]
- 接続時にはユーザー ID とパスワードで認証を行い、かつ双方向で認証が可能。
- 認証方法
    - PAP
        - PPP のコネクション確立時に 1 度だけ ID とパスワードで認証を行う。
        - 暗号化せず平文で送信するので乗っ取りなどの危険性がある。
    - CHAP
        - OTP (One Time Password) を使用して毎回パスワードを変更してやりとりを行う。
        - 毎回パスワードを変更することで乗っ取りなどのリスクを低減し、通信相手が入れ替わっていないかの確認も行える。

# # PPP のフレーム フォーマット
- HDLC (High Level Data Link Control Procedure) プロトコルと同じ方式を用いる。
- 01111110 をフレームの区切りに挟み、フラグ シーケンスと呼ばれる。
- PC がダイアルアップ接続するとき、PPP はソフトウェアで実現されるが、フラグ シーケンスの処理や FCS の処理を CPU で行うため、リソースの負荷が高い。
- フラグ シーケンスの仕様上、1 が 6 つ連続することは許されない。

# # PPPoE (PPP over Ethernet)

- イーサネットのままでは認証機能やコネクション確立/切断がなく、利用時間による課金などの処理もできないが、この機能によりプロパイダが顧客管理をやりやすくなった。

# # ATM (Asynchronous Transfer Mode)
- セルと呼ばれる単位で処理される。
    - データの中身: ヘッダ 5 オクテット + データ 48 オクテット
- 回線の専有時間を短くすることで大容量のデータを効率よく転送できるようにしている。
- ATM の規格化は ITU や ATM フォーラムで行われている。
- 特徴
    - コネクション型のデータリンク。
    - イーサネットや FDDI のような送信権の制御がなく、好きなだけデータ送信が行われるためネットワークが混雑してふくそう状態となってしまうのを防止するために帯域を細かく制御する機能がある。
        ![[Pasted image 20260913173535.png]]
- 同期多重と非同期多重
    - TDM (Time Division Multiplexer) について
        - 複数の通信機器を束ねて 1 つの回線で接続する方式
        - 両端の TDM 同士で同期を行いながら特定の時間単位でデータを区切り宛先ごとに送信する。
        - 宛先ごとにスロットが決まっているいるので空きスロットができ、非効率的。
    - ATM では TDM を拡張して、宛先ごとではなく到着したデータから順番にスロットへ入れていく。このままではどの通信のものか判別ができないため、送信側で 5 オクテットのヘッダを付与して識別する。
        - ヘッダには VPI (Virtual Path Identifier) と VCI (Virtual Channel Identifier) という識別子がついていて、この 2 は通信する ATM 同士での設定となる。
        - 空きスロットが減ることで利用効率があがる反面、識別のためのヘッダが必要になるのでオーバーヘッドが発生し、実際の回線速度から少し低下した速度になる。
	    ![[Pasted image 20260913173553.png]]
- ATM と上位層
    - ATM ではわずか 48 オクテットしかデータを送信することができず、IP ヘッダや TCP ヘッダを付与してしまうとデータ部分がほとんど送れなくなってしまう。そのため、ATM 単独では利用せず、AAL (ATM Adaption Layer) と呼ばれる上位層と利用する。
    - IP の場合は AAL5 と呼ばれる上位層が利用される。
    - 最終的に最大 192 個のセルに分割されて送信される。
	    ![[Pasted image 20260913173611.png]]
    - 性質上、192 個のセルのうち 1 つでもロスが発生すると IP パケットが破壊されて再送なども行われすべてが破棄される。再送を行うには再度 192 個のセルを送信する必要があり、ATM の大きな問題とも言われている。
    - 末端のネットワーク帯域の合計がバックボーンの帯域よりも小さくするなどセルの喪失が発生しにくいようなネットワーク構築が重要となる。
    - ふくそうが発生した場合に ATM コネクションの帯域を動的に変動する技術も研究されている。
	    ![[Pasted image 20260913173626.png]]
