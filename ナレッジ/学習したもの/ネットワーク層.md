# # IP
- Internet Protocol の略。
- データリンクの特性を隠し、どのような経路かに関わらず通信ができる。
- 通信に問題があってもデータ再送などは行わない。

# # ICMP
- Internet Control Message Protocol の略。
- 通信に異常があった際に送信元にそのメッセージを出力するために使用される。
- ネットワーク診断などで使用される。

# # ARP
- Address Resolution Protocol の略。
- MAC アドレスを IP アドレスから取得するためのプロトコル。

# # ネットワークのトポロジーとは
- ネットワークの接続形態、構成形態を指す。
- メッシュ型やスター型、リング型、バス型など様々な構成がある。

# # 媒体共有型のネットワーク
- 媒体共有型と非媒体共有型の ２ つがある。
- 複数のノードが 1 つの媒体を共有する。
- FDDI や初期のイーサネットは媒体共有型。
- 同じ通信経路を使用するので、半二重通信で通信を行う。
- ネットワークで優先権を制御するためにコンテンション方式やトークン パッシング方式がある。

# # コンテンション方式とは
- データの送信権を競争で奪い取る方式 (CSMA 方式)
    - CSMA (Carrier Sense Multiple Access) とは別ノードからのキャリア信号を検出し現在通信を行っているホストがほかにいないか確認する。
- 早い者勝ちで送信権を獲得するので、送信が同時になった場合はコリジョンが発生してネットワーク性能が低下する。

# # CSMA/CD 方式とは
- イーサネットの一部では CSMA 方式を改良した CSMA/CD 方式が採用されている (CD = Colision Detection)。
- CSMA とは異なり、コリジョンを早期に検出し、早々に通信を開放する。
- データが流れていないようならすべてのステーション (データリンクでのノードの呼び方) はデータを送信できる。
- コリジョンが発生しているか検出して、発生している場合は送信をすぐにやめて通信路を開放する。
- 再送する場合は乱数秒待機してから再送する (これはコリジョンを起こした双方がすぐに再送して再度コリジョンが発生しないようにするため)。
- 実際には 32 ビットのジャム信号を送信して送信を停止する。
    - ジャム信号を受け取った側はコリジョン時に受け取ったフレームの FCS と認識して正しい値ではないとしてフレームを破棄する。

# # トークン パッシング方式
- トークンと呼ばれるパケットを巡回させて、このトークンを保持しているステーションだけ送信を行えるようにする。
- トークンを保持しているステーション以外は送信できないため、コリジョンが発生しないため、ネットワークは混雑しても性能の変化があまりない。
- トークンを保持しているステーションしか送信ができないため、混雑していないときは性能を 100% 出しにくい。
- トークン パッシング方式の派生としてアーリートークン リリース方式やアペンド トークン方式などがある。

# # 媒体非共有型のネットワーク
- 通信媒体を共有せず、スイッチはステーションはスイッチに直接接続される。
- 送受信の通信媒体が共有されず、コリジョンも発生しないため、全二重送信となる。
- 現在主流となっている通信方式。
- スイッチに高度な機能を持たせることで VLAN などの構築やデータ流入の制御などが可能。
- スイッチが壊れると接続されているコンピューターの通信ができなくなってします。

# # 共有型の半二重通信/非共有型の全二重通信との違い
- 半二重通信: 送信か受信どちらかしか通信を行うことができない。例えるとレシーバーのような通信方法。
- 全二重通信: 送信と受信を同時に行える。例えると電話のようなもの。
- スイッチとツイストペア ケーブルによってスイッチのポートと PC を接続でき、なおかつ送受信をケーブル内の別々の線で行うことが可能。これによって全二重通信ができる。
- ツイストペア ケーブル内部では通常 8 本 (4 ペア) の芯線が外皮に包まれている。

# # IP はコネクション レス型
- IP はコネクション レス型であり、通信の確立を確認せずに送り続け、通信の確立は上位層に任せられる。これは、一部の通信ではコネクション レス型のままのほうが都合がよい場合があり、コネクションが必要な場合は上位層がその都度実装すれば良いという考え方で設計されている。また、プログラミングの観点からも分けられている方が拡張性や管理のしやすさもある。
- 2 つのブロードキャスト
    - ローカル ブロードキャスト
        - 同一リンク内に対してブロードキャストを行う場合。192.168.0.0/24 のネットワークにブロードキャストする場合は 192.168.0.255 となる。
    - ダイレクト ブロードキャスト
        - 異なるネットワークにパケットを送る際に使用される。192.168.0.0/24 から 192.168.1.0/24 のネットワークに対してブロードキャストを行う場合、192.168.1.255 へパケットを送信する。

# # IP マルチキャストとアドレス
- クラス D のアドレスが使用されて、先頭から 4 ビットまでが 1110 であればマルチキャストとして認識される。残りの 28 ビットがマルチキャストの対象となるグループ番号になる。
    ![[Pasted image 20260913173905.png]]
- マルチキャスト アドレス範囲の使用用途
    - 224.0.0.0 から 239.255.255.255 までが範囲。
    - 224.0.0.0 から 224.0.0.255 までは経路制御されず、同一リンク内でもマルチ キャストになる。
    - それ以外のアドレスは全ネットワーク グループのメンバーへ到達。
- すべてのノードは 224.0.0.1、すべてのルーターは 224.0.0.2 のグループに属する必要がある。
- マルチ キャストを実用的に使用するには、IGMP などを使用する必要がある。

# # サブネットマスク
- サブネットマスク導入以前のクラス A/B/C のアドレス振り分けでは小さな規模の場合は多くの無駄が生じてしまう。この無駄な空きを極力減らすために考えられた仕組み。

# # グローバル アドレスは誰が決めているのか？
- 全世界的に ICANN で一元的に管理されている。
- 日本国内では JPNIC が割り当て機関として活動している。

# # 経路制御 (ルーティング)
- ルーティング テーブルの作成は管理者が作成 (スタティック ルート) するか、他のルーターと情報交換を行ったルーター自身が自動で作成する (ダイナミック ルート) 2 つの方法がある。
- ダイナミック ルートの場合は経路制御情報の交換ができるようにルーティング プロトコルを設定しないといけない。
- IP で通信を行うためにはルーティング テーブルが必須となるが、IP 自身にはルーティング テーブルを作成する機能はなく、ルーティング プロトコルといったプロトコルで作成を行う必要がある。
- IP アドレスと経路制御
    - 表にはネットワーク アドレスとルーターが次に運ぶべき宛先の情報が記載されており、IP パケットを送信する際は宛先の IP アドレスが表にあるかどうかを確認して送信を行う。
    - 複数一致するネットワーク アドレスがある場合は一致するビット列が長いほうを選択する。宛先が 172.20.100.52 の時に 172.20/16 と 172.20.100/24 の 2 つがあれば、一致するビット列が長い 172.20.100/24 の方を選択して送る。
    - 次に配送すべきルーターのアドレスが記載されている箇所に、ホストやルーター自身のネットワーク インターフェースの IP アドレスが記載されている場合は、宛先のホストが同一のデータリンクに接続されていることを指す。

# # デフォルト ルート
- すべてのネットワークやサブネット情報をルーティング テーブルに書くのは無駄が多すぎるため、表に記載のない宛先へはデフォルト ルートを使用して送信される。
- 0.0.0.0/0 または default として扱われる。

# # ホスト ルート
- IP アドレス/32 のことを指す。
- これを使用すると IP アドレスのネットワーク部ではなく、ネットワーク インターフェースに付与されている IP アドレス自体に基づいて経路制御される。
- 何らかの理由によってネットワーク アドレスを使用したくない場合に使用される。
- 経路制御表が肥大化してルーターの負荷が増大する恐れがある。

# # ループバック アドレス
- コンピューター内部のプログラムで通信したい場合に使用され、ネットワークに流れない。
- 127.0.0.1 や [localhost](http://localhost) として扱われる。

# # リンク ローカル アドレス
- ルーターを超えることのない同一データリンク上で 169.254/16 のアドレスで通信が行われる。
- DHCP によるアドレスが自動で取得されなかった場合に設定されたりする。
- ホスト部はランダムに設定されるが、IP アドレスが重ならないように ARP で確認した上で決められる。

# # 経路制御表の集約
- ネットワーク アドレスのビット パターンを考えて階層的に配置を行うと、内部的には複数サブネットワークから構成されていたとしても、外部には 1 つのネットワーク アドレスで経路制御を行えて、ルーティング テーブルを小さくできる。
- ルーティング テーブルが小さくなると、CPU やメモリといったハードディスク リソースを節約することもできる。
- ルーティング テーブルが小さくなると言うことは、他のルーターとの経路情報共有の際にも必要最低限の情報だけを送信できるため、結果としてこれもリソース節約になる。
