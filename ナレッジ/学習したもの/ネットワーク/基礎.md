# # OSI 参照モデル
- 「ブデネトセプア」で覚える
    - ７層：アプリケーション
        - メールの内容など実際に送るデータを扱う
    - ６層：プレゼンテーション
        - データの形式をコンピューター固有の形式からネットワーク共通の形へ変換する
    - ５層：セッション
        - 通信の接続、切断を行う
    - ４層：トランスポート
        - 実際にデータを宛先へ送信する
    - ３層：ネットワーク
        - 宛先までのルートを決定する
    - ２層：データリンク
        - 物理的に接続されているホスト間での通信で使用
        - ホスト間の通信ではMACアドレスを使用して識別している
    - １層：物理
        - １と０の電気信号でデータを実際に送信する
- 送信側は７層 → １層、受け取り側は１層 → ７層の順番で通っていく。

# # 通信機器
- 物理/データリンク層
    - リピーター
        - 通信の信号を増幅するもの。
        - 延長コード的なもの。
        - リピーター ハブといった複数接続できるものもある。
    - ブリッジ
        - データリンク層で機器間の通信を行うためのもの。
        - データリンク レベルではパケットのことをフレームという。
        - ブリッジでは伝送速度が異なる接続でも通すことができる。
        - フレームの流れを学習することができ、壊れたフレームを他のデータリンクに送信しないようにできる。
        - ブリッジ内部には一定期間 MAC アドレスを保持することができ、次回の通信処理が早くなる。
    - スイッチング ハブ
        - ハブのポートごとにブリッジの機能が備わっている。
        - ブリッジの一種
- ネットワーク層
    - ルーター L3 スイッチ
        - ネットワーク層を扱う。
        - 異なるデータリンク間を接続、ルーティングを行う。
- セッション - アプリケーション層
    - ロードバランサ L4 - L7 スイッチ
        - WEB サーバーなど複数用意して通信の負荷分散を行える。
        - 内部的に仮想 URL を用意してその URL からリクエストを受け取り負荷分散を考えながらどのサーバーに送るかを判断。

# # ゲートウェイ
- トランスポート層からアプリケーション層までを扱う (L4-L7 スイッチ)。
- 異なるプロトコル間の通信を行う時に使用する。(言語翻訳のように英語を日本語に変換して理解できるようにするような感覚)
- 同一のプロトコル間の通信はアプリケーション ゲートウェイと呼ばれる (＝プロキシ サーバー)。

# # ネットワークの全体像
- 大まかに コア (バックボーン)/エッジ/アクセス (アグリゲーションとも言う) のように構成されている。
    - コア : 大元の回線。高速に通信を行っている。道路で言うと高速道路。
    - エッジ : コアとアクセス間に位置している回線。高速道路のインターチェンジみたいなもの。
    - アクセス : PC やスマホなどに向かうための回線。道路で言うと下道？

# # SNS などのネットワーク構成環境について
- SNS や Youtube などでは複数のユーザーから大量のデータを保持するために複数のサーバーや大容量のストレージなどで構成されているデータセンターを用意している。
- データセンターの通信は直接バックボーンと接続されていることが多い (なかにはエッジと接続されているものあるよう)。

# # パケットの受信処理
- ネットワーク インターフェース (イーサネット ドライバ) の処理
    - イーサネット パケットを受け取ったホストは宛先 MAC アドレスを確認して自分宛てかどうかを確認する。
    - 自分宛てではない場合はパケットを捨てる (設定で捨てないこともできる)。
    - 自分宛ての場合は次に IP や ARP といったプロトコルを確認してデータに合ったプロトコルへ流す。
- IP モジュールの処理
    - IP ヘッダ処理時にヘッダ内の宛先 IP アドレスが自分宛てかどうかを確認する。
    - 自分宛ての場合は TCP か UDP かを調べて対応したルーチンへデータを渡す。
    - ルーターの場合は大体ルーティング テーブルから次に送るホストかルーターを調べて送信する。
- TCP モジュールの処理
    - チェックサムを計算してデータの破損などを確認する。
    - データが順番通りに受け取られているかを確認したり宛先のポート番号を調べてアプリケーションを特定する。
    - データが届いたかどうかを確認するために送信後、応答を待つ。
    - 送信後、応答がなかったら応答するまで再送を行う。
    - 応答があったらポート番号により特定されたアプリケーションへデータが渡される。
- アプリケーションの処理
    - 送信されたデータをそのまま受け取る。
    - データを解析し、メールを例にするとメールを受け取り宛先人のメールボックスがないようであれば受け取り人がいない旨のデータを送信元へ送信する。
    - ほか容量がいっぱいで受け取れない場合などでも異常終了として送信元へ返す。

# # 公衆アクセス網
- 電話のように KDDI、Docomo といった通信事業者と契約して通信回線を借りる形態のこと。
- アナログ電話回線
    - ダイアルアップ接続を指す。
    - 電話網を使用するので、アナログ信号からデジタル信号に切り替えるモデムが必要になる。
    - 通信速度は 56 kbps と近年では低速で現在はほとんど利用されていない。
    ![[Pasted image 20260913171754.png]]
    
- モバイル通信サービス
    - 1G、2G、PHS、3G 回線など規格化が進み、現在では 4G-LTE や 5G などが主流。
    - 数 Mbps ～ 数十 Mbps 程度のデータ通信が可能。
    - LTE のさらなる大容量、高度化を実現する LTE-Advanced が国際標準団体 3GPP により標準化され、各社、MIMO、キャリア アグリゲーション技術の活用で下り理論値 1 Gbps に近いサービスの提供を開始している。5 G では数 Gbps の通信で Wi-Fi と同程度の通信速度となり低遅延な速度を実現。
        - PHS (Personal Handy-phone System) とは？
            - 回線交換による PIAFS 方式。
            - 最大 64 kbps を提供。その後、高度化によって 800 kbps を実現。
            - さらに PHS 技術を活用したことで 2.5 GHz 帯を利用した広域移動無線システム (BWA) へ進化。現在は 20 Mbps (XGP 方式) ～ 最大 110 Mbps (AXGP 方式) を提供している。
        - MIMO (Multiple-Input and Multiple-Output) とは？
            - 送受信機双方で複数のアンテナを利用して通信品質を向上させる方式。
        - キャリア アグリゲーションとは？
            - 複数の周波数帯の電波を束ねてデータ通信を行う技術。
- ADSL
    - 既存のアナログ電話回線を拡張したもの。
    - アナログ電話回線は高周波のデータ通信を利用できるが、電話局の交換機を通ると電話音声に最適化するために余分な周波数をカットする。そのため交換機を通ると 64 kbps 程度のデジタル信号へ変換が行われ、仕様上 64 kbps 以上の速度を出すのは不可能。そこで、交換機を通る前にスプリッタと呼ばれる分配器を設置し、データ通信用の回線を分離させ速度を出す。
    - ADSL 以外にも VDSL、HDSL、SDSL などがあり、総称して xDSL と呼ばれる。
    - 回線速度は通信方式や電話回線の品質、電話局までの距離にもよるが、ISP から家庭・オフィスへは 1.5 Mbps ～ 50 Mbps、家庭・オフィスから ISP は 512 kbps ～ 2 M bps 程度になる。
        
        ![[Pasted image 20260913171817.png]]
        
- FTTH (Fiber To The Home)
    - 光ファイバーを直接建物内に引き込む方法。
    - ONU という装置を用いて光を電気信号に変換し、PC やルーターへ送られ、常時安定した高速通信が可能。
    - ONU とは？
        - 光回線終端装置。通信会社側の終端装置は OLT (Optical Line Terminal) と呼ぶ。
    - FTTH のほか、建物の直前まで光ファイバーを使用し、そこから先は建物の配線を利用する形態を FTTB (Fiber To The Building)、自宅周辺まで光ファイバーを利用し、周辺の住宅で共有して使用する形態を FTTC (Fiber To The Curb) と呼ぶ。
        ![[Pasted image 20260913171936.png]]
    - 光ケーブルは通常、送信用と受信用で別々にケーブルが用意されているが、FTTH では簡易 WDM を用いて 1 本のケーブルでまかなう。
    - 各家庭に引き込まれる光ケーブルは ONU と OLT の間にある光スプリッタで分岐される。
- ダーク ファイバー
    - 通信事業者や送配電事業者などのインフラ関連の業者が敷いた光ケーブルのうち使用されていない光ケーブルを企業や団体が借り入れられるサービスを指す。
    - 光ファイバーのみの借り入れなので好きな接続方法が可能。
    - 完全に専有することになるので、第三者の侵入を低減することができる。
- ケーブル テレビ
    - 電波を使うテレビ放送をケーブルを使用して放送するサービス。
    - 電波による地上放送はアンテナの設置状況や周辺の建物によって受信状態に影響があるがケーブルを使用するこの方法ではケーブルを使用した通信を行うので比較的影響が少ない。
    - 放送局から加入者宅まではテレビ放送と同じ周波数で通信を行い、加入者宅から放送局へは放送で利用されていない低周波帯を使用する。このため、下りのデータ転送速度にくらべて上りの伝送速度が遅い。
        ![[Pasted image 20260913172026.png]]
    - 加入者は契約時にモデムを受け取り、モデムとケーブル テレビの放送局に設置されているヘッドエンドと呼ばれる装置と通信を行う。
    - ヘッドエンドはデジタル放送や一部のアナログ放送と通信用のデジタル データを 1 つのケーブルで受信できるように変換する。
    - ケーブル テレビ網で DOCSIS という規格が使用され、現在では最大 320 Mbps の通信サービスが行われている。
- 専用回線
    - イーサネット専用線では 1 Mbps ～ 100 Gbps までのサービスが提供されている。
    - SONET/SDH 専用線サービス、ATM 専用線サービスもある。
    - 専用回線の接続形態は必ず 1 対 1 となる。
- VPN
    - IP-VPN、広域イーサネットがある。
    - 近年はインターネットを活用した SD-WAN サービスも提供が開始されている。
    - IP-VPN
        - IP ネットワークに VPN を構築する。
        - IP ネットワーク上に MPLS 技術を用いて VPN を構築するサービスを通信事業者が提供していたりする。
        - MPLS は IP パケットにラベルというものを付与して顧客ごとに異なるように設定することでラベルをもとに宛先を判断する。
        - 複数の顧客の VPN を 1 つの MPLS 網上で区別して、保護されたプライベート ネットワークとして利用できる。顧客ごとに帯域保証などもある。
            ![[Pasted image 20260913172055.png]]
        - 企業が独自に VPN を構築することも可能。この場合は IP-Sec を使用する。
        - IP-Sec によって VPN 上で通信時に IP パケットの認証、暗号化を行い、インターネット上でプライベート ネットワークを構築する。各自が必要とするセキュリティ レベルで通信の暗号化が行えるが、インターネットの混雑状況によっては通信速度に影響が出る場合がある。
- 広域イーサネット
    - 通信事業者で提供する離れた地域を結ぶイーサネット接続のサービス。
    - IP-VPN と違い、データリンク層であるため TCP/IP 以外も利用できる。
    - 通信事業者の VLAN を利用企業が専用で利用する。同じ VLAN であればどこからでもネットワークに接続できる。
    - データリンク層での利用のため、無駄なパケットを流さない工夫が必要になる。
- SD-WAN サービス
    - MPLS やインターネット、4G LTE などを取りまとめて、仮想的な WAN リンクを構成するサービス。
    - 論理ネットワークを構成でき、経路の暗号化、論理ネットワーク上のアプリケーション可視化、クラウド サービス利用時の経路制御などといった機能がある。
- 公衆無線 LAN
    - Wi-Fi (IEEE802.11b など) を利用したサービス。
    - ホットスポットと呼ばれるエリアを駅や店など公共の場に設置して、無線 LAN インターフェースを持ったスマホや PC から接続する。
    - 不特定多数の人が利用するため、暗号化といったようなセキュリティ保護があるか、Web サイトに暗号化があるかなど確認する必要がある。

    - そのほかの公衆通信サービス
        - X.25
            - 電話網の改良版的なネットワーク。
            - 1 つのポイントから複数のサイトに同時接続が可能。
            - 9.6 kbps または 64 kbps の伝送速度をもつ。
            - 現在は使用されていない。
        - フレームリレー
            - X.25 を簡素化して高速化したネットワーク。
            - 1 対 N の接続が可能で、各通信業者から 64 kbps ～ 1.5 Mbps のサービスが提供されていたが、現在は使用されていない。
        - ISDN (Integrated Services Digital Network)
            - 電話、FAX、データ通信など、さまざまな通信を統合して扱うことのできる公衆ネットワーク。現在はほかのサービスへの移行が進み、利用者が減少。
- IP は OSI 参照モデルの第三層に相当
    - ネットワーク層の役割は終端ノード間を通信することにあり、これをエンドツーエンド通信とも呼ばれる。

# # IP アドレスはネットワーク層のアドレス
- データリンク層では識別のために MAC アドレスを使用していたが、ネットワーク層では IP アドレスを使用してネットワークの中から宛先のホストを探す。
- TCP/IP 通信では必ず IP アドレスを設定する必要がある。
    ![[Pasted image 20260913172345.png]]
- データリンク層がPPPであったりイーサネットであったり、どのようなデータリンク層でも関係なく IP アドレス形式は同じになってデータリンク層は抽象化される。
- ブリッジやスイッチング ハブなどでパケットが中継する機器は IP アドレスを設定する必要はなく、これらの機器は IP パケットを 0 や 1 のビット列で伝達したりデータリンク フレームのデータ部として転送するだけなので IP に対応する必要がない。

# # 最終的な宛先ホストまでのパケット配送
- ホップ (hop) は跳ぶという意味があり、TCP/IP ではネットワークの 1 区間のことを指す。
- IP の経路制御はホップ バイ ホップ ルーティングという方式が行われ、この 1 区間ごとに次のルートが決定されてパケットが転送される。
    ![[Pasted image 20260913172426.png]]
- ホップ バイ ホップ ルーティングでは、ルーターやホストは IP パケットを転送するときに到達地点までの経路を指示するわけではなく、経路の中で次の宛先だけを指示する。これを繰り返していくことで最終的に到達地点へたどり着く。
    ![[Pasted image 20260913172447.png]]
- 宅配で例えると、荷物が IP パケットになり、データリンクがトラックとなる。荷物を運ぶトラックは 1 区間ごとに運搬されて次のトラックに乗せ換えて運ばれる。IP でも似たようなことをしている。

# # データリンクの抽象化
- IP は複数のデータリンクで接続されたネットワーク間を通信することになり、データリンクには PPP や無線 LAN、イーサネットなど様々な種類のデータリンクを経由することになるが、IP 以上の層からはデータリンクが抽象化されていてデータリンクの種類に関係なく通信できるようになっている。
- データリンクには、それぞれ MTU (Maximum Transmission Unit) といった最大転送単位が決まっており、データリンク A からデータリンク B へ通信が流れる際に B の MTU が A の MTU より小さい場合がある。この場合はそのままではパケットを送れないので分割して A の MTU に収まるように送信される。
